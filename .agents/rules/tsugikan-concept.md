# ツギカン — プロジェクト憲法

このワークスペースは「ツギカン」というスマホ向けWeb PWAを開発している。以下は全フェーズを通じて常に守るべき制約である。

## このアプリの目的

コミックや小説など巻数のある本について、**書店の棚の前で「自分が何巻まで持っているか」を3秒以内に思い出す**ためのアプリ。

読了記録アプリではない。記録は目的ではなく手段である。判断に迷ったときは常に「書店で3秒」に立ち返ること。

## 3つの憲法

1. **記録の粒度を捨てる** — 1巻ごとのチェックボックスは作らない。シリーズ単位で「所持」「既読」の2つの数字だけを扱う。飛ばし読み、電子と紙の混在、複数所有などのレアケースは意図的に切り捨てる
2. **主役は読了ではなく購入** — 読了は記録されないが購入は記録される。書店で必要なのも「持っている巻」の方である。UIの主語は常に「買った」を先に置く
3. **記録が漏れる前提で作る** — ホーム画面そのものが答えの画面であること。起動してから答えが読み取れるまでに、スプラッシュもチュートリアルも確認ダイアログも挟まない

## 恒久的にスコープ外

要望されない限り、以下を提案・実装しない。

- ユーザー登録、ログイン、クラウド同期、バックエンドサーバー
- 電子書籍と紙の区別、複数所有、貸出管理、評価やレビュー、読書メーター的な統計
- SNS共有、他ユーザーとの連携
- 1巻ごとの個別チェックUI

## 技術の固定事項

- React + TypeScript + Vite
- **UIライブラリ、CSSフレームワーク、状態管理ライブラリを導入しない。** プレーンなCSSと `useState` で書く。依存を増やす提案をする場合は、必ず理由を述べて承認を求めること
- 保存は `localStorage` のみ。キーは `tsugikan.v1`、形式は `{ version: number, series: Series[] }`
- localStorageの読み書きは `useLibrary()` フック1つに閉じ込める。コンポーネントから直接 `localStorage` を触らない
- 保存データが壊れていてもクラッシュさせず、空の状態で起動する
- 基準画面幅は375px。片手操作前提

## データモデル

```ts
type Series = {
  id: string;
  title: string;
  ownedVolumes: number[]; // 所持している巻 例: [1,2,3,5]
  readVolumes: number[];  // 既読の巻
  updatedAt: number;
};
```

内部は配列で保持し、画面では `Math.max()` を取って「◯巻まで」に丸めて表示する。

## 開発フェーズ

現在地を常に意識し、**先のフェーズの機能を先回りして実装しない**こと。

- Phase 1｜骨格：データモデル、localStorage、手動登録、一覧、+1操作。装飾なし
- Phase 2｜命綱：JSONエクスポート／インポート、検索
- Phase 3｜スキャナ：ZXing-js + openBD
- Phase 4｜世界観：配色、フォント、イラスト、アニメーション
- Phase 5｜PWA化：manifest、アイコン、Service Worker、オフライン起動

### Phase 3 で必ず守ること

- `BarcodeDetector` API を使わない（iOS Safariに存在しない）。`@zxing/browser` を使う
- 日本の書籍バーコードは2段ある。上段のISBN（`978`/`979` 始まり）のみ採用し、下段の分類コード（`192` 始まり）は無視する
- 書誌取得は openBD（`https://api.openbd.jp/v1/get?isbn=`）。シリーズ名と巻数は ONIX の構造化フィールドから取得し、**タイトル文字列から正規表現で巻数を剥がす実装は絶対にしない**
- openBDはデータ欠損が普通に起きる。取れない項目は手入力で補えるようにし、エラーで止めない

## エージェントの振る舞い

- **指示にない機能を追加しない。** 良かれと思った先回りは、切り分けを不可能にするので有害である
- 実装に入る前に、構成案とファイル分割を提示して合意を取る
- UIの文言はシステム語ではなくユーザーの言葉で書く（「登録」ではなく「買った」「読んだ」）
- 空状態はエラーではなく招待として書く
- 変更は小さく刻む。1回のタスクで複数の関心事に手を入れない

## 完成の判定

> ポケットから出して、開いて、答えが分かるまでに3秒以内か。

超えている場合、機能を足して解決しようとしないこと。減らして達成する。
